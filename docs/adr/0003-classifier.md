# 0003: Classifier export and precision

Status: Native export, parity and same-model browser precision selection complete.

I ran all five official CLI modes on the 16 pinned upstream images, then exported the v4.0.3a crop classifier. PyTorch-versus-ONNX fp32 parity passed on all 38 classified crops and seeded random batches of sizes one and two: maximum absolute logit difference `3.24249267578125e-05`, below `1e-4`. The fp16 export retained identical top-1 in every case on native ONNX Runtime CPU. Crop pixels matched the official preprocessing byte-for-byte. See [the export workflow](../classifier-export.md) for source hashes, per-image coverage, artifact hashes and reproduction commands.

The fp32 export is 223,998,777 bytes; fp16 is 112,296,562 bytes. Both retain float32 NHWC input `[batch,480,480,3]` and float32 output `[batch,2498]`. Labels, taxonomy and geofence are copied unchanged beside them. The manifest's `local_exports` records their local paths, measured sizes and hashes, with the repository placeholder. Publication is pending.

The manifest currently lists an fp32 v4.0.1a crop classifier and an fp16 v4.0.3b full-image classifier. These are different versions and pipelines, so comparing their latencies cannot establish the precision rule for a single classifier. The crop classifier requires comparison of its own fp16 and fp32 exports on WASM: ship fp16 alone if it runs and its median is at most 1.2 times fp32; otherwise ship both, selecting fp16 for WebGPU and fp32 for WASM.

The browser run on 2026-11-05 (headed Chromium, Apple M5, crossOriginIsolated true, median of 5 zero-tensor runs) answered the rule for the v4.0.3a exports themselves: fp16 runs on WASM at 316.7 ms median against fp32's 323.5 ms, a ratio of 0.98, and on WebGPU at 35.9 ms against 55.8 ms. With the ratio at most 1.2 and native top-1 identical across every golden crop, the manifest ships fp16 only.

Verification retains this measured precision policy when the IDs and SHA-256 values
of all exported files are unchanged, regardless of file ordering. A changed model
or companion asset invalidates the policy and requires new measurements.

## Golden capture correction (2026-11-05)

Re-running `golden/run_cli.py` with the locked reference group reproduced both
reported elephant scores on CPU: `0.741` in an uninterrupted full CLI run and
`0.6293` in the detector-only/classifier-only capture. Neither was a corrupted
inference result. The full capture was the wrong ensemble reference for the
serialized boxes used by the crop parity fixtures.

SpeciesNet 5.0.6's `utils.save_predictions` rounds floats to four decimals.
Its classifier computes integer crop coordinates by truncating each normalized
coordinate multiplied by the image dimension. For detection index 3 in the
2048-by-1536 `african_elephants.jpg`, the in-memory box is
`[0.94189453125, 0.4674478992819786, 0.05810546875, 0.1673177033662796]`.
Its pixel xywh is `[1929, 717, 119, 256]`; the saved box
`[0.9419, 0.4674, 0.0581, 0.1673]` becomes `[1929, 717, 118, 256]`.
That one-pixel width difference changes the classifier input and crosses the
`0.65` species threshold. This is a crop-input difference, not fp16 drift.

The serialized-box raw capture remains authoritative for crop and ensemble
parity. Its regeneration was byte-identical: 51,072 bytes, SHA-256
`03e549a0b45a560df0cea9f0437f4117d5efde6a76f160840ddf26cc139a4ab1`.
The three country outputs were regenerated by the official CLI's
`--ensemble_only` mode using the same saved detector and classifier captures.
All 92 detections and 38 raw top-five classifications now agree exactly across
the four fixtures. The fourth elephant's processed result is `mammal`, score
`0.941`, source `classifier+rollup_to_class`, in each country fixture.
The GBR black bear still exercises `classifier+geofence+rollup_to_order`.

After running the five-mode command in [the export workflow](../classifier-export.md),
the following additional step is required from the repository root, retaining
the documented cache environment and locked reference group. The five-mode script alone
recreates the original mismatch; it is unchanged by this correction.

```sh
export KAGGLEHUB_CACHE="$PWD/.cache/kagglehub"
for country in none usa gbr; do
  country_args=()
  if [ "$country" != none ]; then
    country_args=(--country "$(printf '%s' "$country" | tr '[:lower:]' '[:upper:]')")
  fi
  uv run --project tools --locked --exact --group reference python -m speciesnet.scripts.run_model \
    --folders tests/golden/upstream \
    --ensemble_only \
    --detections_json .cache/deerdiary-cli/detections.json \
    --classifications_json .cache/deerdiary-cli/classifications.json \
    --max_classifications_per_image 5 --max_classifications_per_detection 5 \
    --batch_size 1 --noprogress_bars --ignore_existing_predictions \
    "${country_args[@]}" \
    --predictions_json "tests/golden/speciesnet_cli.$country.json"
done
```

The CLI folder path must match the saved prediction filepaths.
The regression test checks every detection and the threshold-crossing processed
result. These ensemble fixtures describe the serialized-box pipeline; they do
not establish parity with uninterrupted full inference, which uses different
crop pixels. The future end-to-end reference gate must account for that
distinction instead of treating the two capture paths as interchangeable.
